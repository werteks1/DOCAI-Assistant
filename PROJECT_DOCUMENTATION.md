# Документация проекта DocAI Assistant

## Назначение

DocAI Assistant переносит данные с рукописных заявлений в структурированный результат. Обработка выполняется в локальном контуре через Ollama. PaddleOCR находит печатные подписи полей и их координаты, а VLM распознаёт увеличенную полоску с рукописным значением. После этого единый слой проверки форматирует значения, сверяет их со справочником и возвращает предложения для подтверждения пользователем.

## Архитектура

Проект разделён на три слоя.

### 1. Web-приложение

Каталог `web/` содержит React-интерфейс на Vite. Он отвечает за выбор файла, предпросмотр, запуск распознавания, редактирование полей и подтверждение новых слов справочника. В браузере нет ключей Ollama и логики работы с персональными данными: он отправляет документ только локальному API компилятора.

### 2. API компилятора

Каталог `compiler/` содержит FastAPI-приложение.

* `compiler/api.py` — HTTP-контракт `/api/health`, `/api/connect`, `/api/model`, `/api/extract`, `/api/batch` (+`/api/batch/{job_id}` и `/cancel`), `/api/export/excel` и `/api/reference/corrections`.
* `compiler/jobs.py` — фоновые пакетные джобы: глобальная блокировка экстракции (`exclusive_extraction`), последовательное выполнение файлов, polling-состояние, отмена, аннотация дублей.
* `compiler/models.py` — входные и выходные Pydantic-модели (в т.ч. `BatchJobState`).
* `compiler/pipeline.py` — загрузка изображения или всех страниц PDF, предобработка и вызов ядра распознавания. Многостраничный PDF — один ученик: страницы объединяются в одну запись, расхождения помечаются `_conflicts`.
* `compiler/__main__.py` — запуск Uvicorn на `127.0.0.1:8000`.

API не хранит загруженные изображения на диске. Для PDF установлен лимит страниц, для растровых файлов — лимит общего количества пикселей.

### 3. Ядро распознавания и экспорта

Корневые Python-модули выполняют вычислительную работу.

* `document_loader.py` — проверка файлов, EXIF-поворот, коррекция документа, подготовка увеличенных полос и OCR-кропов.
* `field_locator.py` — PaddleOCR PP-OCRv6 как детектор печатных меток. Синонимы меток берутся из активного шаблона `templates.json` (`template_config.load_template`).
* `extractor.py` — запросы к Ollama, строгий JSON-промпт, распознавание полного документа и повторное распознавание отдельных OCR-полосок.
* `validator.py` — нормализация дат, телефонов и СНИЛС, контрольные проверки и согласование фамилии ученика и заявителя.
* `reference_dictionary.py` — локальные списки фамилий, имён, городов и организаций, а также обучаемый файл `reference/custom_corrections.csv`.
* `template_config.py` — загрузка шаблонов бланков из `templates.json` (поля, синонимы меток, резервная геометрия) со встроенным фолбэком.
* `logging_utils.py` — PII-safe логирование с correlation id; в журнал не попадают значения полей и имена файлов.
* `excel_manager.py` — создание и безопасное обновление `.xlsx` без формул, поступивших из распознанного текста; поиск дублей внутри пачки.
* `config.py` — единые настройки моделей, лимитов и функций обработки.

Python-код не содержит графического интерфейса. Каждый рабочий файл ограничен 700–900 строками или меньше; крупный прежний `gui.py` удалён.

## Конвейер одного документа

1. React читает выбранный файл как Data URL и передаёт его в `POST /api/extract`.
2. Компилятор декодирует Base64, проверяет тип и создаёт изображения страниц (для PDF — все страницы).
3. `DocumentLoader` исправляет ориентацию и мягко усиливает рукописный слой.
4. `FieldLocator` запускает PP-OCRv6 и определяет геометрию печатной подписи и строки справа от неё.
5. Для каждого найденного поля создаётся crop с исходными координатами и увеличением. Если PaddleOCR недоступен, используется резервная геометрия шаблона (`fallback_y`/`fallback_x` в `templates.json`) и полный проход VLM.
6. VLM получает только нужную полосу либо полный документ с контекстом и возвращает JSON. Для многостраничного PDF каждая страница читается полным проходом, а результаты объединяются в одну запись.
7. `ReferenceDictionary` предлагает исправления вроде «Бодров → Бобров» и «ГУСД → РЖД». `DataValidator` проверяет формат, контрольную сумму СНИЛС и совпадение фамилий.
8. React показывает результат. Пользователь может отредактировать поле и принять предложение, после чего пара wrong/right добавляется в CSV-справочник.
9. Пакетная обработка выполняется фоном как один джоб: `POST /api/batch` возвращает `{job_id, total}` (202), Web опрашивает `GET /api/batch/{job_id}` до завершения и может вызвать `/cancel`. По завершении джоб помечает дубли внутри пачки (`_duplicates`), а `/api/export/excel` формирует журнал для скачивания. Пока джоб активен, любая другая экстракция получает HTTP 409.

## Запуск

```bash
python3 -m venv venv
source venv/bin/activate
pip install -r requirements-web.txt
./run.sh
```

Интерфейс: `http://127.0.0.1:5173`. API: `http://127.0.0.1:8000/docs`.

По умолчанию компилятор подключается к LAN-серверу `http://192.168.0.19:1234`. При необходимости адрес меняется через переменную `DOCIA_OLLAMA_HOST`. Принимаются только localhost, RFC1918-адреса частных сетей и локальные DNS-имена, которые разрешаются в такую сеть. Адрес `0.0.0.0` использовать нельзя: это адрес прослушивания, а не подключения.

Для включения PaddleOCR установите платформенную сборку из `requirements-ocr.txt` (для macOS Apple Silicon и Python 3.14 может потребоваться отдельное окружение Python 3.10–3.12: у PaddlePaddle нет колеса для всех сочетаний ОС и версии Python). Без PaddlePaddle система продолжает работать через VLM и резервные полосы. Для Ollama заранее загрузите выбранную vision-модель, например `ollama pull qwen2.5-vl:7b`.

## Контракт API

`POST /api/extract` принимает:

```json
{
  "filename": "application.jpg",
  "image_base64": "data:image/jpeg;base64,...",
  "target_columns": ["ФИО поступающего ученика", "СНИЛС поступающего"]
}
```

Ответ содержит `data` со значениями полей и служебным ключом `_reference_corrections`. Предложения не применяются автоматически: пользователь подтверждает каждое изменение в Web-интерфейсе.

`POST /api/batch` принимает массив документов (до 50) и возвращает `202 {"job_id","total"}`. Состояние читается через `GET /api/batch/{job_id}` (статус, `completed`/`total`, текущее сообщение, элементы с полями `data` — они приходят только после завершения джоба, чтобы polling не передавал мегабайты); `POST /api/batch/{job_id}/cancel` помечает отмену между файлами. Распознанный результат каждой записи содержит служебные ключи `_fields`, `_stats` и, при повторе внутри пачки, `_duplicates`. `POST /api/export/excel` принимает записи и отдаёт файл `docai_results.xlsx`; для дублей ставится статус «Возможный дубль».

## Ограничения и дальнейшие шаги

Точность зависит от качества фотографии, почерка, выбранной VLM и наличия справочных значений. Для нового бланка достаточно добавить блок в `templates.json` (поля, синонимы меток, резервные координаты) — код менять не нужно. Перед промышленным использованием соберите набор реальных обезличенных сканов в `test_samples/` (папка в `.gitignore`) и измерьте CER/WER скриптом `evaluate.py` (см. `reference/evaluate_README.md`). Дубли сверяются только внутри текущей пачки — сверка с прошлыми выгрузками остаётся отдельным этапом.
