# Текущие ограничения и план улучшений

После перехода на React и FastAPI список недостатков обновлён. Основные риски связаны
с качеством исходных сканов и настройкой моделей, а не с интерфейсом.

## Ограничения

* PaddleOCR требует совместимую платформенную сборку PaddlePaddle. Если её нет,
  компилятор использует полный проход VLM и резервные полосы из `templates.json`.
* VLM может ошибаться в похожих символах рукописи, например 4/7, Б/Д и Бобров/Бодров.
  Справочник и проверка предлагают исправление, но последнее слово за пользователем.
* Дубли сверяются **внутри текущей пачки** (в памяти). В `docia.db` хранится только
  обезличенный журнал активности (без содержимого документов), поэтому повторный ввод,
  разнесённый по разным выгрузкам, не обнаруживается.
* Один PDF трактуется как один ученик: страницы объединяются в одну запись. Файл с
  несколькими разными заявлениями автоматически не разделяется.
* Одиночный запрос во время пакетной обработки получает быстрый отказ (409): ядро
  распознавания не потокобезопасно, поэтому экстракции сериализуются одной блокировкой.

## Что уже закрыто

* Python GUI удалён; отображение перенесено в `web/` (React); API — в `compiler/` (FastAPI).
* OCR, VLM, валидатор, справочник и экспорт разделены на модули.
* Выбор приоритета `OCR + VLM` / только полосы PaddleOCR / только VLM и medium/small
  детектора PP-OCRv6.
* **Многостраничный PDF = один ученик:** все страницы распознаются и объединяются в
  одну запись, расхождения между страницами помечаются `needs_review` (`_conflicts`).
* **Пакетный джоб с честным прогрессом:** последовательная фоновая обработка,
  polling состояния `GET /api/batch/{id}`, отмена, `409` при занятой экстракции.
* **Дубли внутри пачки:** сверка СНИЛС / ФИО+даты рождения, аннотация
  `_duplicates`, жёлтый маркер в UI и статус «Возможный дубль» в Excel.
* **Логирование без персональных данных:** в лог не попадают значения полей и имена
  файлов; у записей есть correlation id (`logging_utils.py`).
* **Вход с ролями (оператор / администратор), сессии и статистика:** первый вход
  `admin/admin` с принудительной сменой пароля; роли проверяются на сервере; консоль
  администратора (сервер ИИ / пользователи / статистика); защита от перебора. Учётки,
  сессии и обезличенный журнал активности — в `docia.db` (`.gitignore`).
* **Шаблон бланка в JSON:** поля, синонимы меток и резервная геометрия перенесены в
  `templates.json` (`template_config.py`); при порче файла — встроенный фолбэк.
* **Замер точности:** `evaluate.py` считает CER/WER по размеченному набору.
* Исправления в `reference/custom_corrections.csv` — после явного подтверждения.
* Ограничены PDF по страницам/пикселям и адреса серверов ИИ; значения перед записью
  в Excel обезвреживаются от формул.

## Следующие шаги

1. Собрать обезличенный набор сканов и прогнать `evaluate.py` — получить цифры
   CER/WER для слайда презентации.
2. Добавить тесты для `validator.py`, `reference_dictionary.py`, `field_locator.py`
   и `ExcelManager` (выбрано пользователем вне текущего объёма).
3. Сверка с прошлыми выгрузками (постоянный журнал на сервере) — отдельным этапом,
   если потребуется защита от повторов между пачками.
