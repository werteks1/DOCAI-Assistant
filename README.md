# 📑 DocAI Assistant
> **Локальное приложение на базе искусственного интеллекта для автоматизации обработки рукописных школьных документов и ведения Excel-отчетности.**
> Индивидуальный итоговый проект по информатике за 10 класс.

---

## 🔒 Локальная обработка
Приложение рассчитано на работу с локальной мультимодальной нейросетью через **Ollama** или любым OpenAI-совместимым сервером: адрес сервера не ограничивается. При подключении к внешнему адресу персональные данные могут покинуть локальный контур; используйте только доверенный сервер.

Логирование — без персональных данных: в журнал не попадают значения распознанных полей и имена исходных файлов (см. [logging_utils.py](logging_utils.py)).

Доступ к системе — через вход с ролями **пользователь / администратор** (см. ниже). Публичных эндпоинтов, кроме `/api/health` и `/api/auth/login`, нет.

---

## 🚀 Быстрый запуск

### Web-версия

Проект разделён на три слоя:

* `web/` — React-интерфейс для загрузки документа, просмотра результата и подтверждения исправлений;
* `compiler/` — FastAPI-контур (API + фоновые пакетные джобы);
* ядро Python (`document_loader.py`, `field_locator.py`, `extractor.py`, `validator.py`, `reference_dictionary.py`, `excel_manager.py`, `template_config.py`) — OCR/VLM, проверки, шаблоны и экспорт.

### Воспроизводимая установка

Версии прямых зависимостей зафиксированы точно (`==`), поэтому окружение
собирается одинаково на разных машинах:

```bash
python -m venv venv
./venv/bin/pip install -r requirements-web.txt   # веб-путь: VLM, экспорт, API
```

OCR-детектор PP-OCRv6 требует совместимой платформенной сборки PaddlePaddle,
поэтому ставится в отдельное окружение Python 3.10–3.12 (диапазон версий — не пин):

```bash
python3.11 -m venv venv-ocr
./venv-ocr/bin/pip install -r requirements-ocr.txt
```

Фронтенд собирается из lock-файла воспроизводимо (`npm ci`):

```bash
cd web && npm ci && npm run build
```

Запуск:

```bash
./run.sh
```

Откройте `http://127.0.0.1:5173`. API компилятора работает на `http://127.0.0.1:8000`.

Без OCR-окружения API автоматически использует полный проход VLM.

### Windows (двойной клик)

Для Windows есть [start.bat](start.bat): при первом запуске он сам создаёт `venv`,
устанавливает зависимости и собирает интерфейс, затем поднимает сервер и открывает
браузер на `http://127.0.0.1:8000` (вход `admin` / `admin`, пароль нужно сменить).
Нужны Python 3.10+ и — только для первой сборки интерфейса — Node.js LTS. Если
Windows спросит про брандмауэр, разрешите доступ: иначе другие ПК класса не смогут
открыть сервер по сети.

### Несколько ПК по школьной сети (режим класса)

Один компьютер школы становится сервером и раздаёт и API, и собранный интерфейс —
остальные ПК работают через браузер, ничего не устанавливая:

```bash
cd web && npm run build   # собрать интерфейс в web/dist (папка в .gitignore)
python -m compiler        # компилятор слушает 0.0.0.0:8000
```

Ученики открывают `http://<IP-сервера>:8000` (всё через один порт: вход, документы,
консоль администратора `/settings`). При первом запуске создаётся `docia.db` — учётки,
сессии и обезличенный журнал активности; файл в `.gitignore`. Локальная разработка без
сборки остаётся на Vite: `./run.sh` (порт :5173 проксирует `/api` и `/settings` на компилятор).

### 🔑 Вход и роли

* Все действия — после входа. При первом запуске (пустая база) создаётся учётка
  **`admin` / `admin`**; при первом входе программа потребует **сменить временный пароль** —
  до этого настройки и обработка документов недоступны.
* **Пользователь (оператор)** — только документы: загрузить, распознать, поправить поля,
  скачать Excel. Без настроек, учётных записей и статистики.
* **Администратор** — создаёт учётные записи операторов, настраивает «куда уходит запрос»
  (консоль `http://<сервер>:8000/settings`: список подключений к серверам ИИ, активное
  подключение, модель, параметры), смотрит обезличенную статистику использования.
* Пароли хранятся как PBKDF2-хеш (соль на каждого пользователя), сессии — случайные
  токены в SQLite `docia.db`; после 5 неудачных попыток входа аккаунт блокируется на 15 минут.

### Подключение к Ollama / LM Studio:
* По умолчанию используется LAN-сервер `http://192.168.0.19:1234`.
* Если модель запущена на другом компьютере, задайте `DOCIA_OLLAMA_HOST` перед запуском.
* Модель выбирается через `DOCIA_MODEL`; список моделей сервера появляется в поле «Модель ИИ».
* Уровень журнала и файл лога — `DOCIA_LOG_LEVEL`, `DOCIA_LOG_FILE`.
* Активный шаблон бланка — `DOCIA_TEMPLATE` (имя из `templates.json`).

Все перечисленные настройки сервера/модели администратор меняет без перезапуска в
**консоли администратора** (`http://127.0.0.1:8000/settings`, вход под ролью `admin`):
список **подключений** (адрес + API-ключ + выбранная модель) с пресетами Ollama и LM Studio,
произвольными OpenAI-совместимыми адресами (vLLM, llama.cpp, облачные API) и параметрами
запроса. Подключения сохраняются в `settings.json` (файл в `.gitignore`), добавляются,
переключаются, правятся и удаляются из интерфейса; активно ровно одно — его адрес, ключ и
модель применяются сразу и переживают перезапуск компилятора. Старые настройки с одиночным
адресом мигрируют в первое подключение автоматически.

## 🛠 Возможности системы

1. **Одиночный документ с верификацией (Human-in-the-Loop):**
   * Поддержка изображений (`.png`, `.jpg`, `.jpeg`) и PDF-документов (`.pdf`).
   * **PDF = один ученик:** все страницы растеризуются и распознаются, значения полей объединяются в одну запись; расхождения между страницами помечаются «проверить».
   * Адаптивная предобработка сканов: повышение контраста и резкости для считывания шариковой ручки.
   * Просмотр документа слева и редактируемые поля справа.
   * Выбор приоритета `OCR + VLM`, только PaddleOCR-полосы или только VLM, детектор PP-OCRv6 medium/small.
   * Подтверждение исправлений справочника прямо в браузере.

2. **Компилятор:**
   * PaddleOCR находит координаты печатных меток и полос рукописных строк; без него используется резервная геометрия из `templates.json`.
   * Шаблон бланка (поля, синонимы меток, резервные координаты) — в [templates.json](templates.json); новый бланк добавляется без правки кода.
   * Валидатор проверяет даты, телефоны, СНИЛС и совпадение фамилий.
   * **Пакетный режим — честный прогресс:** Web-интерфейс отправляет документы последовательно и показывает «обработано X из N». Кнопка «Отменить» отправляет серверу отмену текущего запроса, закрывает поток ответа ИИ и останавливает очередь; повторный запуск доступен после завершения отмены. Для API-клиентов также доступна фоновая очередь `/api/batch`. Две экстракции одновременно невозможны (запрос получает 409).
   * **Загрузка сканов:** учитывается EXIF-поворот фото; изображения и страницы PDF ограничены 25 млн пикселей, проверка выполняется до декодирования или растеризации. В одном PDF — до 20 страниц.
   * **Защита от повторного ввода:** в пределах пачки сравниваются СНИЛС и ФИО+дата рождения; дубли помечаются в интерфейсе и выгружаются в Excel как «Возможный дубль».
   * Результаты пакета скачиваются единым Excel-файлом; статус каждой записи — «Проверено», «Возможный дубль» или «Требует проверки» (цвет ячейки соответствует статусу).
   * **Окно проверки:** крупный скан с масштабом, перемещением и страницами PDF; поля сгруппированы, спорные — под фильтром «Требуют сверки»; каждый документ подтверждается кнопкой «Подтвердить» (отметка снимается при ручной правке).
   * **Замер точности:** [evaluate.py](evaluate.py) считает CER/WER по полям на размеченном наборе (`reference/evaluate_README.md`).

3. **Консоль администратора** (кнопка ⚙ в шапке или `http://127.0.0.1:8000/settings`, только роль `admin`), три вкладки:
   * **Сервер и модель** — сохранённые **подключения** к серверам ИИ: адрес, API-ключ (хранится локально, в интерфейсе — только маска) и модель. Форма добавляет подключение по пресетам **Ollama** (11434), **LM Studio** (1234), **SiliconFlow**, **Google AI Studio** (родной Gemini API), **SeekAI**, облачным API или произвольному OpenAI-совместимому адресу; в списке — «Подключить», «Проверить», «Изменить», «Удалить». Активное подключение выделено; при удалении активного система сама переключается на доступное.
     * Для облаков действует предупреждение о персональных данных: изображения заявлений уходят на сторонний сервер. У Google на бесплатном тарифе данные могут использоваться для улучшения продуктов — для документов детей подходит только платный тариф либо локальные модели (Ollama/LM Studio).
   * Список моделей сервера подтягивается сам при выборе адреса или пресета (и по кнопке «Проверить»), а на больших каталогах (OpenRouter и др.) появляется поиск по названию модели. Выбранная модель применяется сразу и запоминается в подключении. Параметры распознавания VLM: температура, `top_p`, лимит токенов ответа, таймаут запроса, дополнительная системная инструкция. Параметры хранятся в `settings.json` + локальная копия формы в браузере.
   * **Пользователи** — создание учётных записей операторов/администраторов, сброс пароля, блокировка/удаление.
   * **Статистика** — обезличенный журнал активности (кто, действие, время, успех/ошибка) без имён файлов и значений полей.

4. **Ограничения:**
   * PaddleOCR требует совместимую сборку PaddlePaddle (на Python 3.14 без неё — чистый VLM).
   * Дубли сверяются **внутри текущей пачки**; постоянного журнала на сервере нет, поэтому «двойник» из прошлой выгрузки не обнаруживается.
   * Один PDF считается одним учеником; файл, содержащий несколько разных заявлений, не разделяется автоматически.
